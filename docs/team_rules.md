## ブランチと Pull Request（PR）
- main には直接コミットしない。
- ブランチ名: `<タスクID>-<短い説明>`（例: `T-003-face-detect`）
- PR の説明に、対応するタスクID・REQ・テスト結果を書く。
- PR は作成者以外の1人以上がレビューし、承認（Approve）してからマージする。承認なしにマージしない。
- マージする人: 〈例: 承認の後に作成者がマージする〉
- マージの後、全員が `git switch main` と `git pull` で main を最新にする。

## 連絡
- 決定事項は Slack ではなく文書（requirements.md / design.md）に残す。
- 作業を始めるとき・PR を出したときに Slack で知らせる。
- 返信の目安: 24時間以内
