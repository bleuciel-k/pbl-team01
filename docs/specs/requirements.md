- バージョン: v0.5
- チーム: 1 
- 最終更新日: 2026-11-24

## 1. 背景と目的
（どんな人の、どんな困りごとを、画像処理・画像認識でどう解決するか）
手で操作できるゲームを作って、たくさんの人に楽しんでほしい
手での操作を検出する部分を、画像処理・画像認識によって実装する。

## 2. ユーザーストーリー
- US-01: ユーザーとして、開始直後にタイトル画面が表示されてほしい。難易度等の設定を行うため。
- US-02: ユーザーとして、難易度の設定を行いたい。自分にあった難しさのゲームを遊ぶため。
- US-03: ユーザーとして、タイトル画面で操作方法の確認を行いたい。初めてでは操作方法がわからないため。
- US-04: ユーザーとして、タイトル画面からゲームをスタートして戦闘を開始したい。
- US-05: ユーザーは、相手のターンのとき、制限時間内に特定の手のポーズをとることで、相手の攻撃を回避（防御）できる。
- US-06: ユーザーは、自分のターンのとき、特定の手のポーズをとることで、行動（7種のスキルコマンド）を選択して実行できる。
- US-07: （スコープ外・実装見送り）ユーザーは、自分のターンのとき、カメラで撮影した物体をアイテムとして追加できる。（Q-009の決定により7種のスキルのみで戦う仕様に統一）
- US-08: ユーザーは、複数ウェーブの連戦においてすべての相手の体力を0にすることで、戦闘に勝利する。

## 3. スコープ
### 対象
- 画面表示
- 入力
  - キーボード（メニュー操作、単体攻撃時のターゲット切り替え、勝敗決定後の画面遷移など）
  - カメラ認識
    - 手のポーズ分類（自分のターンの7種スキル、相手のターンの10種回避ポーズ）
- SE
- グラフィック

### 対象外
- 本格的なRPGマップ
- カメラ撮影によるアイテム追加機能（US-07 / REQ-007：Q-009の決定によりスコープ外）

## 6. 機能要求
### REQ-001: タイトル画面の表示
- 説明: アプリケーション起動直後にタイトル画面を表示し、難易度設定、操作方法の確認、およびゲーム開始を選択できるようにする。
- 対応US: US-01
- 受け入れ基準:
  - AC-001-1: アプリケーションを起動したとき、システムはタイトル画面を表示しなければならない。
  - AC-001-2: タイトル画面を表示しているとき、システムは「ゲーム開始」「難易度設定」「操作方法の確認」へ進むための選択肢を画面上に提示しなければならない。
  - AC-001-3: （異常系）起動時に必要な画像・音声素材またはモデルファイルが存在しない・読み込めないとき、システムはエラーメッセージを表示して安全に終了（またはユーザーに通知）しなければならない。
- 優先度: Must

### REQ-002: 難易度の設定
- 説明: タイトル画面においてゲームの難易度を Easy / Normal / Hard の3段階（デフォルト: Normal）から選択・変更できるようにする。難易度によって戦闘の各ウェーブでランダム選出される敵の出現パターン候補（例: 「スライム1」「スライム2、スケルトン1」等）が変化する（相手ターンの防御制限時間は難易度に関わらず一定）。
- 対応US: US-02
- 受け入れ基準:
  - AC-002-1: ユーザーがタイトル画面で難易度（Easy / Normal / Hard）を選択・変更する操作を行ったとき、システムは選択された難易度を保持し、現在選択中の難易度を画面上に表示しなければならない。
  - AC-002-2: ユーザーがゲームを開始したとき、システムは設定された難易度に対応する敵の出現パターン候補からランダムに敵編成を選出して戦闘を初期化しなければならない。
  - AC-002-3: （異常系）ユーザーが難易度の変更操作を行わずにゲーム開始を選択したとき、システムはデフォルトの難易度（Normal）を適用して戦闘を開始しなければならない。
  - AC-002-4: （異常系）難易度選択中に割り当て外の無効なキー入力が行われたとき、システムは現在の難易度設定を変更せず表示を維持しなければならない。
- 優先度: Must

### REQ-003: 操作方法の確認（ヘルプ表示）
- 説明: タイトル画面（および画面仕様に基づき戦闘画面のヘルプ）で、手のポーズ（7種のスキル・10種の回避ポーズ）やキーボードによる操作方法を確認できるようにする。
- 対応US: US-03
- 受け入れ基準:
  - AC-003-1: ユーザーがタイトル画面またはゲーム画面で操作方法（ヘルプ）の表示操作を行ったとき、システムは使用する手のポーズ一覧とゲームの操作説明を画面に表示しなければならない。
  - AC-003-2: 操作方法の表示中にユーザーが閉じる（戻る）操作を行ったとき、システムは操作方法の表示を終了して元の画面に戻らなければならない。
  - AC-003-3: （異常系）操作方法を表示している最中にカメラに手のポーズが映った、または戻る操作以外の無関係なキーが入力されたとき、システムは戦闘行動などを誤って実行せず操作方法の表示を維持しなければならない。
- 優先度: Must

### REQ-004: 戦闘の開始と戦闘画面（GUI・カメラ映像）の表示
- 説明: タイトル画面からゲームをスタートして戦闘画面へ遷移し、画面仕様（`UI.png`）に定義された6つの領域（手の見本のアイコン、認識結果のアイコン、ゲーム画面、カメラ映像、ダイアログ、自分のHP/MP/状態）を表示・更新する。
- 対応US: US-04
- 受け入れ基準:
  - AC-004-1: ユーザーがタイトル画面でゲーム開始操作を行ったとき、システムは戦闘画面へ遷移し、「手の見本のアイコン」「認識結果のアイコン」「ゲーム画面（敵キャラクター、敵HP、タイマー、ヘルプ、設定）」「カメラ映像」「ダイアログ」「自分のHP, MP, 状態」を画面に表示して戦闘を開始しなければならない。
  - AC-004-2: 戦闘中、カメラから映像フレームを取得したとき、システムは「カメラ映像」領域にリアルタイムの映像を表示し、現在の認識結果に応じた画像を「認識結果のアイコン」領域に表示しなければならない。
  - AC-004-3: （異常系）戦闘開始時または戦闘中にカメラデバイスが接続されていない、またはカメラ映像の取得に失敗したとき、システムはエラーメッセージを画面またはダイアログに表示し、進行を一時停止（または再接続・終了を案内）しなければならない。
- 優先度: Must

### REQ-005: 手のポーズ認識による自分のターンの行動選択・実行
- 説明: 自分のターンのとき、カメラ映像から特定の手のポーズを **3秒以上連続して同じポーズとして認識** することで、以下の7種のスキルコマンドから行動を選択・決定して実行し、結果に応じて敵HP・自分のHP・MP・状態（バフ・状態異常）・ダイアログ・SEを反映する。また、単体攻撃のターゲットはキーボードの左右キー（または番号キー）で切り替えられるようにする。
  - **自分のターンの7種スキルコマンド**:
    1. `vサイン`：**一刀両断**（敵単体 / 攻撃力:中 / 命中率:高 / 消費MP:なし）
    2. `グーパンチ`：**正拳突き**（敵単体 / 攻撃力:そこそこ高 / 命中率:低 / 消費MP:なし）
    3. `右向き指差し`：**マジックショット**（敵全体 / 攻撃力:中 / 命中率:高 / 消費MP:少 / 備考:余裕があれば敵ごとに確率でクリティカル発生）
    4. `人差し指と親指を交差`：**ラブアンドピース**（自分HP回復 / 消費MP:そこそこ / 備考:正拳突きとの識別精度次第で別ポーズへ変更の可能性あり）
    5. `手（パー）`：**ガードフォーム**（2ターンの間、受けるダメージが半分に減る / 消費MP:少）
    6. `電話して`：**力だめ**（MPが増え、次のターンでの攻撃力が約1.7倍に上がる / 消費MP:なし）
    7. `閲覧者に向いた人差し指`：**必殺技 ヒーロースマッシュ**（敵単体に強力な魔法攻撃［余裕があれば他の敵にも中ダメージ］ / 攻撃力:とても高 / 命中率:必中 / 消費MP:大）
- 対応US: US-06
- 受け入れ基準:
  - AC-005-1: 自分のターンのとき、7種のスキルコマンドのいずれかに対応する手のポーズが3秒以上連続して認識されたとき、システムはコマンドを決定して「認識結果のアイコン」を更新し、対応するスキルを実行して「ダイアログ」に行動ログを表示しなければならない。
  - AC-005-2: 自分のターンで単体攻撃スキルを実行するとき、システムはキーボードの左右キー（または番号キー）によって選択されている敵キャラクターをターゲットとして効果を適用し、効果音（SE）を再生して敵のHPまたは自分のHP・MP・状態（バフ・状態異常）の表示を更新してターンを進行させなければならない。
  - AC-005-3: （異常系）自分のターンのとき、カメラに手が映っていない、どの登録ポーズにも該当しない、または同じポーズの継続時間が3秒未満で別のポーズに変わったとき、システムはコマンドを決定せず誤実行してはならない。
  - AC-005-4: （異常系）自分のターンのとき、必要なMPが不足しているスキルのポーズが3秒以上入力されたとき、システムはMP不足で実行できない旨を「ダイアログ」に表示し、自分のターンを消費せずに再入力を待たなければならない。
  - AC-005-5: （異常系）自分のターンのとき、相手ターンの回避専用ポーズ（`+1`、`okサイン`、`上向き指差し_1` 等）など自分のターンで無効なポーズが入力されたとき、システムは行動を実行せず入力待機状態を維持しなければならない。
- 優先度: Must

### REQ-006: 手のポーズ認識による相手ターンの攻撃回避（防御）
- 説明: 相手のターンのとき、各敵キャラクターが攻撃してくる際に10種のポーズ（`+1`、`グーパンチ`、`vサイン`、`人差し指と親指を交差`、`okサイン`、`手`、`電話して`、`右向き指差し`、`上向き指差し_1`、`閲覧者に向いた人差し指`）からランダムに指定された見本の手のポーズを制限時間内にとることで、敵の攻撃を回避（ダメージ0）する。また、敵の攻撃によって状態異常（毒・麻痺など）が発生する場合があり、プレイヤーの状態（ガードフォームによる被ダメ半減バフ等）と合わせて処理する。
- 対応US: US-05
- 受け入れ基準:
  - AC-006-1: 相手のターンで敵が攻撃を行うとき、システムは10種のポーズからランダムに選んだターゲットポーズを「手の見本のアイコン」に表示し、ゲーム画面のタイマーで一定の制限時間（難易度に関わらず一定）のカウントダウンを開始しなければならない。
  - AC-006-2: 制限時間内に「手の見本のアイコン」と一致する手のポーズが **3秒以上連続して認識された** とき、または **制限時間が0になった（時間切れの）瞬間のポーズが見本と一致していた** とき、システムは回避成功と判定してその攻撃のダメージを0にし、回避成功のログを「ダイアログ」に表示して効果音（SE）を再生しなければならない。
  - AC-006-3: （異常系）制限時間内に見本と同じポーズが3秒以上継続せず、かつ時間切れになった瞬間のポーズも見本と一致しなかった（または手が認識されなかった）とき、システムは回避失敗と判定して被ダメージ（ガードフォーム中は半減）や敵の状態異常効果（毒・麻痺等）を自分に適用し、被ダメージ・状態変化のログを「ダイアログ」に表示しなければならない。
- 優先度: Must

### REQ-007: カメラ撮影によるアイテム追加（スコープ外）
- 説明: 自分のターンのとき、カメラで撮影した物体を認識してゲーム内のアイテムとして追加する機能。Q-009の決定により、本作では7種のスキルコマンド体系に統一するため **スコープ外（実装見送り）** とする。
- 対応US: US-07
- 受け入れ基準:
  - （スコープ外のため対象外）
- 優先度: Won't（スコープ外）

### REQ-008: 複数ウェーブ連戦の進行と戦闘の勝利判定
- 説明: 戦闘は複数ウェーブの連戦（例: 第1戦→第2戦→ボス戦）で構成され、各ウェーブでは難易度に応じた出現パターンから選出された1体〜複数体の敵が登場する。すべてのウェーブのすべての相手の体力を0にすることで戦闘に勝利し、戦闘画面上に勝利メッセージを表示してキー操作でタイトル画面へ戻る。
- 対応US: US-08
- 受け入れ基準:
  - AC-008-1: 現在のウェーブのすべての敵キャラクターのHPが0以下になったとき、次のウェーブが存在する場合は次のウェーブの敵出現パターンを登場させて戦闘を継続し、最終ウェーブのすべての敵のHPが0以下になった場合は戦闘勝利と判定して勝利メッセージおよび演出をゲーム画面と「ダイアログ」に表示しなければならない。
  - AC-008-2: 戦闘勝利メッセージが表示されている状態でユーザーが所定のキー操作（Enter等）を行ったとき、システムはタイトル画面へ遷移しなければならない。
  - AC-008-3: （異常系）敵キャラクターが複数存在するウェーブで一部の敵のHPのみが0以下になって他にHPが1以上の敵が残っているとき、システムはウェーブクリアや戦闘勝利とせず戦闘を継続し、すでにHPが0になった敵の攻撃やその敵への単体攻撃ターゲット選択を行わせてはならない。
- 優先度: Must

### REQ-009: 戦闘の敗北判定と戦闘終了後の誤操作防止
- 説明: 相手の攻撃や状態異常（毒など）によって自分のHPが0になったときに敗北判定を行い、戦闘画面上に敗北メッセージを表示してキー操作でタイトル画面へ戻る。また、戦闘終了（勝利または敗北）後はポーズ認識による戦闘行動を受け付けないようにする。
- 対応US: US-05, US-08
- 受け入れ基準:
  - AC-009-1: 相手の攻撃等の結果、自分のHPが0以下になったとき、システムは自分のHP表示を0に更新して戦闘敗北（ゲームオーバー）と判定し、敗北メッセージをゲーム画面と「ダイアログ」に表示しなければならない。
  - AC-009-2: 戦闘敗北メッセージが表示されている状態でユーザーが所定のキー操作（Enter等）を行ったとき、システムはタイトル画面へ遷移しなければならない。
  - AC-009-3: （異常系）戦闘の勝利または敗北が確定した後にカメラに特定の手のポーズが映ったとき、システムは追加のスキル実行・回避などの戦闘行動を実行してはならない。
- 優先度: Must

## 7. 非機能要求
### NFR-001: 開発言語・実行環境
- 説明: チーム開発および仕様駆動開発の制約（`AGENTS.md`）に従い、Python 3.10 以上の環境で統一して動作すること。
- 受け入れ基準:
  - AC-NFR-001-1: Python 3.10 以上の標準的な実行環境において、構文エラーやランタイム非互換なく起動・動作しなければならない。

### NFR-002: 使用ライブラリの制限
- 説明: `AGENTS.md` で許可されたライブラリ（OpenCV, NumPy, PyQt5, MediaPipe）のみを使用し、無断で外部ライブラリを追加しないこと。
- 受け入れ基準:
  - AC-NFR-002-1: ソースコード内で `import` される外部ライブラリが、仕様書および `AGENTS.md` で合意されたライブラリ（OpenCV, NumPy, PyQt5, MediaPipe）およびPython標準ライブラリのみで構成されていなければならない。

### NFR-003: 対応OS（マルチプラットフォーム動作）
- 説明: `AGENTS.md` の制約に従い、Windows と macOS の2環境を公式対応とし、両方の環境で動作すること。
- 受け入れ基準:
  - AC-NFR-003-1: Windows および macOS の両環境において、ファイルパスやカメラデバイス指定、GUI描画のOS依存エラーを起こさずにタイトル画面から戦闘終了まで一通り動作しなければならない。

### NFR-004: カメラ映像およびポーズ認識のリアルタイム性能
- 説明: 相手のターンの制限時間内に手のポーズをとって回避するゲーム性を損なわないよう、カメラ映像の表示とポーズ認識が十分な応答速度で動作すること。
- 受け入れ基準:
  - AC-NFR-004-1: 戦闘画面においてカメラ映像の更新および手のポーズ認識処理を行ってもGUIがフリーズせず、制限時間タイマーのカウントダウンとユーザーのポーズ入力に対してリアルタイム（目安として10fps以上、認識遅延0.5秒以内）に応答しなければならない。

### NFR-005: 手のポーズ認識精度
- 説明: `data/test_images/` に配置したテスト画像を用いて、手のポーズ分類の認識精度を定量的に検証できること。
- 受け入れ基準:
