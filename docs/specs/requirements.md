## 1. 背景と目的
（どんな人の、どんな困りごとを、画像処理・画像認識でどう解決するか）
手で操作できるゲームを作って、たくさんの人に楽しんでほしい
手での操作を検出する部分を、画像処理・画像認識によって実装する。

## 2. ユーザーストーリー
- US-01: ユーザーとして、開始直後にタイトル画面が表示されてほしい。難易度等の設定を行うため。
- US-02: ユーザーとして、難易度の設定を行いたい。自分にあった難しさのゲームを遊ぶため。
- US-03: ユーザーとして、タイトル画面で操作方法の確認を行いたい。初めてでは操作方法がわからないため。
- US-04: ユーザーとして、タイトル画面からゲームをスタートして戦闘を開始したい。
- US-05: ユーザーは、相手のターンのとき、制限時間内に特定の手のポーズをとることで、相手の攻撃を防御できる
- US-06: ユーザーは、自分のターンのとき、特定の手のポーズをとることで、行動(攻撃orアイテム使用)を選択して実行できる。
- US-07: ユーザーは、自分のターンのとき、カメラで撮影した物体をアイテムとして追加できる。(可能なら)
- US-08: ユーザーは、すべての相手の体力を0にすることで、戦闘に勝利する。

## 3. スコープ

## 6. 機能要求
### REQ-001: タイトル画面の表示
- 説明: アプリケーション起動直後にタイトル画面を表示し、難易度設定、操作方法の確認、およびゲーム開始を選択できるようにする。
- 対応US: US-01
- 受け入れ基準:
  - AC-001-1: アプリケーションを起動したとき、システムはタイトル画面を表示しなければならない。
  - AC-001-2: タイトル画面を表示しているとき、システムは「ゲーム開始」「難易度設定」「操作方法の確認」へ進むための選択肢を画面上に提示しなければならない。
  - AC-001-3: （異常系）起動時に必要な画像・音声素材またはモデルファイルが存在しない・読み込めないとき、システムはエラーメッセージを表示して安全に終了（またはユーザーに通知）しなければならない。
- 優先度: Must

### REQ-002: 難易度の設定
- 説明: タイトル画面においてゲームの難易度を選択・変更できるようにする。
- 対応US: US-02
- 受け入れ基準:
  - AC-002-1: ユーザーがタイトル画面で難易度を選択・変更する操作を行ったとき、システムは選択された難易度を保持し、現在選択中の難易度を画面上に表示しなければならない。
  - AC-002-2: ユーザーがゲームを開始したとき、システムは設定された難易度に応じたパラメータ（制限時間や敵の強さ等）で戦闘を初期化しなければならない。
  - AC-002-3: （異常系）ユーザーが難易度の変更操作を行わずにゲーム開始を選択したとき、システムはあらかじめ定められたデフォルトの難易度を適用して戦闘を開始しなければならない。
  - AC-002-4: （異常系）難易度選択中に割り当て外の無効なキー入力が行われたとき、システムは現在の難易度設定を変更せず表示を維持しなければならない。
- 優先度: Must

### REQ-003: 操作方法の確認（ヘルプ表示）
- 説明: タイトル画面（および画面仕様に基づき戦闘画面のヘルプ）で、手のポーズやキーボードによる操作方法を確認できるようにする。
- 対応US: US-03
- 受け入れ基準:
  - AC-003-1: ユーザーがタイトル画面またはゲーム画面で操作方法（ヘルプ）の表示操作を行ったとき、システムは使用する手のポーズ一覧とゲームの操作説明を画面に表示しなければならない。
  - AC-003-2: 操作方法の表示中にユーザーが閉じる（戻る）操作を行ったとき、システムは操作方法の表示を終了して元の画面に戻らなければならない。
  - AC-003-3: （異常系）操作方法を表示している最中にカメラに手のポーズが映った、または戻る操作以外の無関係なキーが入力されたとき、システムは戦闘行動などを誤って実行せず操作方法の表示を維持しなければならない。
- 優先度: Must

### REQ-004: 戦闘の開始と戦闘画面（GUI・カメラ映像）の表示
- 説明: タイトル画面からゲームをスタートして戦闘画面へ遷移し、画面仕様（`UI.png`）に定義された6つの領域（手の見本のアイコン、認識結果のアイコン、ゲーム画面、カメラ映像、ダイアログ、自分のHP/MP/状態）を表示・更新する。
- 対応US: US-04
- 受け入れ基準:
  - AC-004-1: ユーザーがタイトル画面でゲーム開始操作を行ったとき、システムは戦闘画面へ遷移し、「手の見本のアイコン」「認識結果のアイコン」「ゲーム画面（敵キャラクター、敵HP、タイマー、ヘルプ、設定）」「カメラ映像」「ダイアログ」「自分のHP, MP, 状態」を画面に表示して戦闘を開始しなければならない。
  - AC-004-2: 戦闘中、カメラから映像フレームを取得したとき、システムは「カメラ映像」領域にリアルタイムの映像を表示し、現在の認識結果に応じた画像を「認識結果のアイコン」領域に表示しなければならない。
  - AC-004-3: （異常系）戦闘開始時または戦闘中にカメラデバイスが接続されていない、またはカメラ映像の取得に失敗したとき、システムはエラーメッセージを画面またはダイアログに表示し、進行を一時停止（または再接続・終了を案内）しなければならない。
- 優先度: Must

### REQ-005: 手のポーズ認識による自分のターンの行動選択・実行
- 説明: 自分のターンのとき、カメラ映像から特定の手のポーズを認識することで、行動（攻撃またはアイテム使用）を選択して実行し、結果に応じてHP・MP・状態・ダイアログ・SEを反映する。
- 対応US: US-06
- 受け入れ基準:
  - AC-005-1: 自分のターンのとき、カメラ映像から行動（攻撃またはアイテム使用）に対応する特定の手のポーズが認識・確定されたとき、システムは「認識結果のアイコン」を更新し、対応する行動を実行して「ダイアログ」に行動ログを表示しなければならない。
  - AC-005-2: 自分のターンで攻撃またはアイテム使用が実行されたとき、システムは対応する効果音（SE）を再生し、敵のHPまたは自分のHP・MP・状態の表示を更新してターンを進行させなければならない。
  - AC-005-3: （異常系）自分のターンのとき、カメラに手が映っていない、またはどの登録ポーズにも該当しない（判別不能・確信度不足の）手が映っているとき、システムは未認識状態として扱い、行動を誤実行してはならない。
  - AC-005-4: （異常系）自分のターンのとき、所持数が0のアイテムを使用するポーズ、または必要なMPが不足している行動のポーズが入力されたとき、システムは実行できない旨を「ダイアログ」に表示し、自分のターンを消費せずに再入力を待たなければならない。
  - AC-005-5: （異常系）自分のターンのとき、相手のターン用の防御専用ポーズなど自分のターンで無効なポーズが入力されたとき、システムは行動を実行せず入力待機状態を維持しなければならない。
- 優先度: Must

### REQ-006: 手のポーズ認識による相手ターンの防御
- 説明: 相手のターンのとき、制限時間内に指定された見本の手のポーズをとることで、相手の攻撃を防御する。
- 対応US: US-05
- 受け入れ基準:
  - AC-006-1: 相手のターンが開始されたとき、システムはターゲットとなる手のポーズを「手の見本のアイコン」に表示し、ゲーム画面のタイマーで制限時間のカウントダウンを開始しなければならない。
  - AC-006-2: 相手のターンの制限時間内に、「手の見本のアイコン」と一致する手のポーズが認識されたとき、システムは防御成功と判定して相手の攻撃によるダメージを軽減（または無効化）し、防御成功のログを「ダイアログ」に表示して効果音（SE）を再生しなければならない。
  - AC-006-3: （異常系）相手のターンの制限時間内に見本と異なる手のポーズしか認識されなかった、または手が認識されないまま制限時間が0になった（タイムアウトした）とき、システムは防御失敗と判定して通常の被ダメージを自分のHPに適用し、被ダメージのログを「ダイアログ」に表示しなければならない。
- 優先度: Must

### REQ-007: カメラ撮影によるアイテム追加
- 説明: 自分のターンのとき、カメラで撮影した物体を認識してゲーム内のアイテムとして追加できるようにする（拡張機能）。
- 対応US: US-07
- 受け入れ基準:
  - AC-007-1: 自分のターンのとき、ユーザーがカメラで物体を撮影してアイテム化する操作を行ったとき、システムは撮影された画像から物体（または画像特徴）を判定し、対応するアイテムを所持リストに追加して「ダイアログ」に獲得ログを表示しなければならない。
  - AC-007-2: （異常系）撮影された画像から有効な物体が検出できなかった、またはアイテムの所持上限に達しているときに撮影操作が行われたとき、システムはアイテム追加に失敗した旨を「ダイアログ」に表示し、所持アイテムを変更してはならない。
- 優先度: Could

### REQ-008: 戦闘の勝利判定
- 説明: すべての相手の体力を0にすることで戦闘に勝利し、勝利時の画面表示を行う。
- 対応US: US-08
- 受け入れ基準:
  - AC-008-1: 自分の行動の結果、すべての敵キャラクターのHPが0以下になったとき、システムは敵のHP表示を0に更新して戦闘勝利と判定し、勝利メッセージおよび演出をゲーム画面と「ダイアログ」に表示しなければならない。
  - AC-008-2: （異常系）敵キャラクターが複数存在し、一部の敵のHPのみが0以下になって他にHPが1以上の敵が残っているとき、システムは戦闘勝利とせず戦闘を継続し、すでにHPが0になった敵の行動やその敵への攻撃対象選択を行わせてはならない。
- 優先度: Must

### REQ-009: 戦闘の敗北判定と戦闘終了後の誤操作防止
- 説明: 相手の攻撃によって自分のHPが0になったときに敗北判定を行い、戦闘終了（勝利または敗北）後はポーズ認識による戦闘行動を受け付けないようにする。
- 対応US: US-05, US-08
- 受け入れ基準:
  - AC-009-1: 相手の攻撃等の結果、自分のHPが0以下になったとき、システムは自分のHP表示を0に更新して戦闘敗北（ゲームオーバー）と判定し、敗北メッセージをゲーム画面と「ダイアログ」に表示しなければならない。
  - AC-009-2: （異常系）戦闘の勝利または敗北が確定した後にカメラに特定の手のポーズが映ったとき、システムは追加の攻撃・アイテム使用・防御などの戦闘行動を実行してはならない。
- 優先度: Must

## 7. 非機能要求
### NFR-001: 開発言語・実行環境
- 説明: チーム開発および仕様駆動開発の制約（`AGENTS.md`）に従い、統一されたプログラミング言語およびバージョンで動作すること。（具体的なバージョンの確定は未決事項 Q-011 参照）
- 受け入れ基準:
  - AC-NFR-001-1: チームで合意したPythonバージョン（例: Python 3.10以上）の標準的な実行環境において、構文エラーやランタイム非互換なく起動・動作しなければならない。

### NFR-002: 使用ライブラリの制限
- 説明: `AGENTS.md` で許可されたライブラリのみを使用し、無断で外部ライブラリを追加しないこと。（具体的な許可ライブラリの確定は未決事項 Q-012 参照）
- 受け入れ基準:
  - AC-NFR-002-1: ソースコード内で `import` される外部ライブラリが、仕様書および `AGENTS.md` で合意されたライブラリ（例: OpenCV, NumPy, PyQt5 等）のみで構成されていなければならない。

### NFR-003: 対応OS（マルチプラットフォーム動作）
- 説明: `AGENTS.md` の制約に従い、Windows と macOS の両方の環境で動作すること。（詳細は未決事項 Q-013 参照）
- 受け入れ基準:
  - AC-NFR-003-1: Windows および macOS の両環境において、ファイルパスやカメラデバイス指定、GUI描画のOS依存エラーを起こさずにタイトル画面から戦闘終了まで一通り動作しなければならない。

### NFR-004: カメラ映像およびポーズ認識のリアルタイム性能
- 説明: 相手のターンの制限時間内に手のポーズをとって防御するゲーム性を損なわないよう、カメラ映像の表示とポーズ認識が十分な応答速度で動作すること。
- 受け入れ基準:
  - AC-NFR-004-1: 戦闘画面においてカメラ映像の更新および手のポーズ認識処理を行ってもGUIがフリーズせず、制限時間タイマーのカウントダウンとユーザーのポーズ入力に対してリアルタイム（目安として10fps以上、認識遅延0.5秒以内）に応答しなければならない。

### NFR-005: 手のポーズ認識精度
- 説明: `data/test_images/` に配置したテスト画像を用いて、手のポーズ分類の認識精度を定量的に検証できること。（具体的な目標値は未決事項 Q-004 参照）
- 受け入れ基準:
  - AC-NFR-005-1: `data/test_images/` 配下の各ポーズのテスト画像セットを入力したとき、システムは合意された正解率基準（例: 各ポーズ10枚中8枚以上）で正しいポーズラベルを出力しなければならない。
